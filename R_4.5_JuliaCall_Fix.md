# R 4.5.5 JuliaCall Fix Documentation

## Problem Summary

**Issue**: `JuliaCall::julia_console()` fails on R 4.5.5 because R 4.5 no longer exports the `SET_SYMVALUE` symbol that RCall.jl requires.

### Dependency Chain

The issue stems from a dependency chain:

- **JuliaCall** (R package) depends on **RCall.jl** (Julia package)
- RCall.jl is the Julia package that provides the R ↔ Julia interface
- When JuliaCall starts, it loads RCall.jl in the Julia environment
- **The CRAN version of RCall.jl does not yet have the patch** for R 4.5 compatibility

### Installation Context

**Note**: JuliaCall was installed using `remotes` (not from CRAN):

```r
library(remotes)
# JuliaCall installation via remotes
```

This is relevant because:

- Remotes allows installing from GitHub, which may have different dependencies
- The Julia environment managed by JuliaCall still pulls RCall.jl from the Julia package registry
- Even if JuliaCall itself is from GitHub, the RCall.jl dependency comes from the standard Julia package ecosystem

### Root Cause

When `JuliaCall::julia_console()` runs, it attempts to:

1. Start Julia
2. Load `JuliaCall/julia/setup.jl`
3. Load `RmdJulia.jl` (which depends on RCall.jl)
4. RCall.jl calls `SET_SYMVALUE` → **❌ R 4.5 no longer exports this symbol → crash**

The failure occurs **before** you ever get a Julia prompt, which is why this approach fails even though it's usually correct. The issue is that the **CRAN/registry version of RCall.jl hasn't been updated** with the R 4.5 compatibility patch yet, so we must manually install the patched version from GitHub.

## Workaround Solution (Temporary Fix)

**⚠️ Important**: This is a temporary escape hatch, not a long-term solution. RmdJulia support may still be fragile, updates can overwrite your patched RCall, and this is not CRAN-supported.

### Step-by-Step Fix

#### 1️⃣ Start Julia Directly (NOT from R)

Run this in Terminal:

```bash
/Users/markpampuch/Library/Application\ Support/org.R-project.R/R/JuliaCall/julia/1.9.4/julia-1.9.4/bin/julia
```

You should see:

```

```

✅ This works because Julia itself is fine.

#### 2️⃣ Install the Patched RCall.jl in Julia

In the Julia REPL:

```julia
using Pkg
Pkg.add(url="https://github.com/JuliaInterop/RCall.jl", rev="3563a24")
Pkg.resolve()
```

Then verify:

```julia
Pkg.status("RCall")
```

You must see a GitHub URL with that commit.

#### 3️⃣ Verify JuliaCall's Environment

Still in Julia:

```julia
Base.active_project()
```

You should see something like:

```
.../JuliaCall/julia/environments/v1.9
```

If you don't, note what it prints.

#### 4️⃣ Return to R and Retry

In R:

```r
JuliaCall::julia_setup(force = TRUE)
```

Then test:

```r
JuliaCall::julia_eval("1 + 1")
```

## Clean Solution (Recommended for Production)

**🟢 For real analysis (ALDEx2, Bioconductor, papers):**

👉 **Install R 4.4.x and stop here**

This avoids:

- Manual Julia patching
- Fragile environments
- Mysterious future failures
